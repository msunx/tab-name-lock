## 它解决了什么

很多后台、文档和控制台拥有相同或不断变化的页面标题。标签定名把自定义名称绑定到 Chrome 的 `tab.id`：同一个网址打开多次也能分别命名，刷新、前进后退或跨域跳转不会串名。

```text
当前标签页 → 保存「🚀 生产环境」→ 刷新 / 跳转后继续显示
关闭标签页 → 删除本次名称
```

- **按标签页隔离**：不使用 URL、域名、窗口位置或原标题作为关联键。
- **名称保持稳定**：网页脚本、通知数量和 SPA 路由更新标题时，扩展会恢复自定义名称。
- **关闭即清除**：关闭标签页或整个窗口后，不再保留对应名称。
- **Emoji 前缀**：内置 96 个常用表情，也支持粘贴组合 Emoji。
- **界面适配**：支持 Chrome 横向、纵向标签页，以及浅色、深色模式。
- **状态提醒**：鼠标选中页面上的状态文字，只有从指定的 A 变为 B 时才发送系统通知。

## 安装

当前版本通过 Chrome 开发者模式加载：

```bash
git clone git@github.com:msunx/tab-name-lock.git
```

1. 打开 `chrome://extensions`。
2. 开启右上角的「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择克隆得到的 `tab-name-lock` 目录。
4. 将「标签定名」固定到工具栏，打开普通网页后即可使用。

macOS 默认快捷键为 <kbd>Option</kbd> + <kbd>Shift</kbd> + <kbd>R</kbd>。可在 `chrome://extensions/shortcuts` 中修改。

更新代码后，在扩展管理页点击「重新加载」，并刷新已打开的网页。重新加载扩展会开始新的命名会话。

## 使用

1. 打开需要辨认的标签页，点击扩展图标。
2. 输入名称；需要时从左侧选择 Emoji。
3. 点击「保存名称」。之后在当前标签页中刷新或换网址，名称仍会保留。
4. 点击「恢复原标题」可提前清除；直接关闭标签页也会自动清除。

## 页面状态监听

例如，发布页面中的状态从「发布中」变为「发布完成」时，让 Chrome 发出系统通知：

1. 打开扩展弹窗，展开「状态监听」，点击「选择元素」。
2. 在网页上移动鼠标，高亮需要监听的文字，点击选中；这次点击不会触发所选网页按钮或链接。按 Esc 可取消。
3. 浮层会用当前文字预填状态 A，输入状态 B，点击「开始监听」。也可以重新选择元素。
4. 之后在扩展弹窗查看当前状态、编辑规则、暂停/继续或删除。点击系统通知会回到原标签页并聚焦所属窗口。

<p align="center">
  <img src="./assets/readme/monitor-editor.png" width="900" alt="在发布状态演示页选择状态文字，并配置发布中到发布完成的提醒">
</p>

每个标签页一条规则，持续监听。A、B 去除首尾空白并合并连续空白、换行后，必须与元素整段可见文字完全一致。例如「发布中 50%」不等于「发布中」，「发布成功」也不等于「发布完成」。请以页面实际显示的文字配置 A、B。

匹配只依据文本；颜色、样式和其他属性变化不参与匹配。文字与装饰性 SVG 图标同时更新时也会继续判断状态转换。

| 观察到的变化 | 是否通知 |
| --- | --- |
| 发布中 → 发布完成 | 通知一次 |
| 发布中 → 失败 → 发布完成 | 不通知 |
| 首次看到发布完成，或文字始终是发布完成 | 不通知 |
| 发布中 → 发布完成 → 发布中 → 发布完成 | 通知两次 |

- 规则跟随当前标签页。同一网址刷新后，重新寻找元素并接续上一次状态；换网址、查询参数或 hash 后，自动寻找所选元素并从当前文字重新开始。Chrome 内置页等不支持监听的页面保留规则，回到普通网页后恢复寻找元素。
- OPS 后续发布单也会继续监听，无需重新配置。换页后首次看到「发布成功」只记录当前状态，不把上一页的「发布中」与新页面的「发布成功」拼成提醒；之后每次「发布中 → 发布成功」都会触发。
- 通过站内路由进入页面后可直接配置，无需先刷新。切到其他标签页后继续观察；临时通信失败会按顺序重试，切回时同步失败也会自动恢复，不会因此停止监听。
- 手动暂停后继续、修改并保存规则，都会从当前文字重新建立基线。取消编辑保留原规则。
- 元素消失时显示「等待元素」，重新出现后继续；无法唯一定位时显示「需重新选择」，不会任取一个匹配元素。页面布局大幅变化后建议重新选择。
- 规则只属于当前标签页，不随相同网址共享。移动到其他窗口时保留，复制标签页不继承，关闭标签页或窗口后清除。
- 「测试通知」可检查通知链路。若 Chrome 已发送但屏幕上没有显示，请检查 macOS 的 Chrome 通知设置与专注模式。

## 行为边界

| 操作 | 结果 |
| --- | --- |
| 刷新、前进后退、换网址或域名 | 保留当前标签页的名称 |
| 同一网址打开多个标签页 | 分别命名，互不影响 |
| 标签页移动到另一个 Chrome 窗口 | 名称跟随标签页移动 |
| 复制标签页或重新打开相同网址 | 新标签页不继承名称 |
| 关闭标签页或包含它的窗口 | 删除名称 |
| 完全退出并重启 Chrome | 开始新的命名会话 |

## 权限与隐私

扩展没有账号、服务器、分析统计或远程代码。名称、监听规则、元素最近文字与通知关联仅保存在浏览器内存中的 `chrome.storage.session`，不会上传或同步到其他设备。
关闭对应标签页会删除其记录；重启浏览器、更新或重新加载扩展会清空本次会话。系统通知会显示标签名称或网页标题以及配置的 A → B 文字。

| 权限 | 用途 |
| --- | --- |
| `storage` | 在当前浏览器会话中保存标签页名称、监听规则和最近状态 |
| `tabs` | 识别标签页 ID，响应跳转、移动和关闭事件 |
| `scripting` | 为已经打开的网页补充标题保持与元素选择脚本 |
| `notifications` | 状态满足 A → B 时发送系统通知，支持测试通知与点击返回页面 |
| `webNavigation` | 区分刷新、换页及 SPA 路由变化，拒绝旧页面的延迟消息 |
| `http://*/*`、`https://*/*` | 保持标题，并在配置监听的页面读取所选元素的文字 |

## 浏览器限制

- Chrome 不允许普通扩展修改 `chrome://` 页面、新标签页、扩展商店、其他扩展页面及部分内置查看器的标题。回到普通 HTTP/HTTPS 网页后，已保存名称会继续生效。
- Chrome 没有直接设置原生标签标题的扩展 API，本项目通过网页的 `document.title` 实现。导航开始到内容脚本运行之间，可能短暂显示网址或网页原标题。
- 当前版本不处理 `file://` 本地文件。
- 若把网站访问权限改成「点击时允许」，跨网站跳转后的自动保持会受到限制。
- 状态监听首版支持主文档的可见 DOM 文本；不支持 iframe、网页组件内部的 Shadow DOM、Canvas 或输入框的 value。
- 监听只依据网页实际呈现且能观察到的状态，不读取发布系统接口、不自动刷新页面。无法还原中间状态的复杂 DOM 更新会重新建立基线，优先避免误报。
- 页面被冻结、丢弃、电脑休眠或网页本身不再更新时，无法持续观察。重新加载同网址后会接续最近状态，但不会知道休眠期间未显示的中间过程。

## 开发与验证

扩展使用 Manifest V3 和原生 JavaScript，运行本身不需要构建步骤。浏览器验收使用 Playwright：

```bash
npm install
npx playwright install chromium
npm run verify:browser
npm run verify:popup
```

`verify:browser` 覆盖名称隔离、动态标题、Emoji、鼠标选择、严格状态转换、批量 DOM 变化、规则生命周期、通知次数和错误反馈；通知自动验收使用浏览器内的通知 API 替身，避免向系统批量发通知。
`verify:popup` 会打开真实工具栏弹窗，检查高度、Emoji 滚动区域和保存操作。系统横幅及点击返回需在 macOS 实际验证。

项目结构：

```text
├── manifest.json       # 扩展清单与权限
├── background.js       # 标签页生命周期与会话数据
├── content.js          # 页面标题保持
├── naming.js           # 名称与 Emoji 处理
├── monitor-*.js         # 元素选择、状态监听与系统通知
├── popup.*             # 工具栏弹窗
├── icons/              # 扩展图标
└── scripts/            # 浏览器验收脚本
```
